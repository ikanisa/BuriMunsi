# BuriMunsi operator acceptance

The designated operator performs or witnesses the actions and records the result. Engineering checks, store availability, and an installed version are separate evidence. Start with the normal workday and read-only observation; do not make a test transfer, clear app data, interrupt the field receiver, print credentials, enrol a device, or replay any payment.

## 1. Identify the release

Record these once in the approved private acceptance record: operator and role, start and end in Kigali time, Staff and Admin Sync app version and distribution path, Admin web revision, backend revision, and private test group alias. The relevant app authority is the signed-in person's profile. Android permission and source attribution are technical conditions, not handset or SIM approvals.

## 2. Observe the real workflows

| Check | What the operator should observe |
| --- | --- |
| Staff | An authorized Staff user signs in, can read their expected group and member statement, cannot perform Admin-only actions, and the Staff app does not capture SMS. Sign out from the separate test session and confirm private data is no longer visible. |
| Admin | An authorized Admin can open the expected group in Android and web Admin. Check consent and capture state without changing production permissions, and inspect one authorized payment and its matching member statement. Do not allocate or adjust as a test shortcut. |
| Ordinary receipt | Start the observation before an independently witnessed normal incoming MoMo payment. Follow the [fresh receipt witness](fresh-receipt-witness.md). Record one same-reference payment and linked SMS, then check again after normal processing. No real receipt in the window means **pending**, not failed or passed. |
| Reconcile | Where in release scope, the appropriate custodian uses the [wallet cutoff check](wallet-acceptance.md) and independent bank records. An app record is not bank-settlement evidence. Leave any mismatch unresolved with its original identity. |
| Distribution | On a separate, eligible approved managed profile, follow [managed Play acceptance](managed-play-device-acceptance.md). Record new install and upgrade separately for each app. |
| Interrupted sessions and revoked access | Exercise only on the designated non-field profile or test environment. Verify the pending request is accounted for by original identity and revoked access no longer sees private data. Never replay an uncertain submission or disable the receiving Admin just to test. |

For each applicable row record **Passed / Failed / Pending**, actual observation, time and protected evidence reference. Document omitted checks and their reason separately. Do not keep receipt bodies, names, amounts, device IDs or statements in Git. Link the [physical carrier acceptance](../../native/burimunsi/configuration/physical-carrier-acceptance.md) evidence where it is a release requirement.

## 3. Decide separately from QA

The designated operator records **Accept / Do not accept / Pending**, date, outstanding exceptions and their owner, and what was actually witnessed. Unexplained money, privacy, authorization or receipt-continuity discrepancies remain release blockers. Do not use this sheet as a substitute for the existing signed promotion guard or for a finance/bank approval.
