# BuriMunsi qualification without paid CI

Use this for a reviewed commit in an isolated checkout, with no production credentials or real customer data. It does not publish, deploy, sign a release, or replace a required GitHub check.

1. Confirm the checkout and candidate are the right revisions:
   `git status --short && git rev-parse HEAD`. Preserve unpublished local work separately before synchronizing. Run both `make check-source` and `bash scripts/release_secret_scan.sh` from the clean checkout.
2. Use **Node 24.19.0** as pinned by `.github/workflows/ci.yml`. Install the locked Admin dependencies with `npm ci --prefix admin-web --no-audit --no-fund` and `npm ci --prefix deploy/platform-admin --ignore-scripts --no-audit --no-fund`. Run `make test-admin` and `node --test admin-web/tests/pwa/package-pwa.test.mjs`. Install the Playwright Chromium version pinned by `admin-web` (use Playwright's OS dependency instructions for the test host), then run `make admin-fixture` and `node admin-web/tests/browser/smoke.mjs build/admin-web-fixture`. If running the hosting check, use only the public fixture value `sb_publishable_admin_build_fixture_only` and the build/verify commands from the workflow.
3. Run the Edge job with **Deno 2.9.6** and the exact PostgreSQL 17.10 container digest and loopback fixture in the workflow. Use a disposable Linux runner/container with no secrets, a fresh private fixture directory, and the workflow's synthetic-only variables. Do not point the tests at hosted Supabase. Record tests that skip a missing PostgreSQL fixture as **NOT RUN**, not passed.
4. For Android, use `.github/workflows/burimunsi-native.yml` and the pinned local Gradle/SDK. Build from the isolated checkout with `make native-build NATIVE_OUTPUT=/absolute/private/new-output`. Preserve manifests, APK checksums, and variant identity, then instrument the designated synthetic emulators for minimum and target APIs. These are qualification builds, not signed release artifacts and not carrier, handset commissioning, or operator UAT.
5. Record exact source commit and candidate diff, environment/tool versions, commands, exit codes, and private evidence references. Keep unverified gates visible. Re-run against the integrated remote commit if it changes.

## Get genuine automated check results back onto the PR

GitHub documents that [standard hosted runners are free for public repositories](https://docs.github.com/en/actions/concepts/billing-and-usage). If an account restriction still prevents jobs from starting and an automated GitHub result is required, a free-tier external CI provider is possible only after the repository owner enables an approved integration, reviews its quota and data access, and confirms the rule accepts results from that integration. Keep equivalent checks and use the actual run status for the precise commit; [GitHub supports requiring a specific check source](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches). Do not post a passing check on behalf of a job that did not run. Do not register the owner's Mac as a runner for a public repository: [untrusted workflow code can persistently compromise self-hosted runners](https://docs.github.com/en/actions/reference/security/secure-use).
